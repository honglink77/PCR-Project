# iProduct 与 PCR Workbench — 本地启动、同步与部署

**更新日期：** 2026-09-08  
**适用仓库：** `iProduct_Project`（门户）+ `PCRworkbench_Project`（Product Ops 工作台）

相关设计：`docs/superpowers/specs/2026-09-08-iproduct-pcr-nav-design.md`

## 1. 日常怎么用（只起一个服务）

日常演示、联调 **只启动门户**：

```powershell
cd iProduct_Project
npm run dev
```

浏览器打开终端里提示的地址（常见为 `http://localhost:5173` 或 `5174`）。

| 操作 | 结果 |
|------|------|
| 门户 Workspace 点 **Product Ops** | 打开 PCR Overview（同标签页） |
| PCR 顶栏点 **iProduct** | 回到门户首页 |

**不需要**再单独启动 PCR 的第二个服务。PCR 页面已挂在门户同一站点下。

## 2. `public` 目录是什么

路径：`iProduct_Project/public/`

在 Vite 项目里，`public` 里的文件会：

- 开发时：直接按路径访问（不经过打包编译）
- 构建时：原样拷贝到 `dist/`

本项目中与 PCR 相关的是：

```
iProduct_Project/public/
  workbench/
    pcr-workbench-proto.html   ← PCR 工作台单页（生成副本）
```

访问地址（开发）：

```text
http://localhost:<端口>/workbench/pcr-workbench-proto.html
```

### 重要约定

| 项 | 说明 |
|----|------|
| **谁是源码** | 只改 `PCRworkbench_Project/src/`，再 `node build.mjs` 生成 `PCRworkbench_Project/pcr-workbench-proto.html` |
| **谁是副本** | `public/workbench/pcr-workbench-proto.html` 由脚本从上面那份 **复制** 而来 |
| **禁止** | 不要手改 `public/workbench/` 里的 HTML；下次 sync 会被覆盖，且与源码分叉 |

把 `public/workbench` 理解成：「给门户挂载用的 PCR 成品页缓存」，不是编辑入口。

## 3. 特殊说明：改了 PCR 界面之后怎么更新到 public

改 PCR ≠ 改门户 React。门户不会自动监视 `PCRworkbench_Project/src`。  
正确顺序固定为两步：

### 步骤 A — 在 PCR 工程里重新生成单页

```powershell
cd PCRworkbench_Project
node build.mjs
```

生成 / 更新：`PCRworkbench_Project/pcr-workbench-proto.html`

### 步骤 B — 同步到 iProduct 的 `public/workbench`

任选其一：

**方式 1（推荐，最省事）**  
停掉再开门户开发服务（`predev` 会自动 sync）：

```powershell
cd iProduct_Project
npm run dev
```

**方式 2（dev 已在跑、不想重启）**

```powershell
cd iProduct_Project
npm run sync:workbench
```

然后在浏览器对 PCR 页 **强制刷新**（Ctrl+F5）。

### 同步脚本做了什么

- 命令：`npm run sync:workbench` → `node scripts/sync-workbench.mjs`
- 复制：

  `PCRworkbench_Project/pcr-workbench-proto.html`  
  → `iProduct_Project/public/workbench/pcr-workbench-proto.html`

- 自动时机：`npm run dev` 前的 `predev`、`npm run build` 前的 `prebuild`

### 一句话记忆

> **改 PCR 源码 → `build.mjs` → sync（或重启 `npm run dev`）→ 刷新浏览器**  
> 只重启 iProduct、却忘了先 `build.mjs`，门户里仍是旧 PCR。

## 4. 只改门户（iProduct）时

改 `iProduct_Project/src/` 下的 React 代码即可。  
Vite 热更新一般会自动刷新，**不必**为 PCR 再跑 `build.mjs` / sync。

## 5. 生产构建与部署（简述）

在门户目录：

```powershell
cd iProduct_Project
npm run build
```

流程：

1. `prebuild` → 自动 `sync:workbench`（把最新 PCR HTML 拷进 `public/workbench`）
2. `vite build` → 产出 `dist/`（含 `dist/workbench/pcr-workbench-proto.html`）

将 **`dist/` 整目录** 部署到静态站点即可。部署后：

- 门户：`/`
- PCR：`/workbench/pcr-workbench-proto.html`

部署前请确认 PCR 侧已先执行过最新的 `node build.mjs`，否则 sync 拷的是旧单页。

`npm run preview` 预览的是已有 `dist/`，**不会**自动再 sync；改完 PCR 后应重新 `npm run build` 再 preview。

## 6. 常见问题

**Q：点 Product Ops 还是旧界面？**  
A：是否漏了 `node build.mjs`？是否漏了 sync / 重启 `dev`？是否浏览器缓存（试 Ctrl+F5）？

**Q：能直接改 `public/workbench/*.html` 吗？**  
A：不要。改 `PCRworkbench_Project/src`，走 build → sync。

**Q：要不要同时开两个终端分别跑两个项目？**  
A：日常不用。只跑 `iProduct_Project` 的 `npm run dev`。只有改 PCR 源码时才进 `PCRworkbench_Project` 执行 `build.mjs`。

**Q：sync 报 Missing source？**  
A：先到 `PCRworkbench_Project` 执行 `node build.mjs`，确保 `pcr-workbench-proto.html` 存在后再 sync。

| 日常启动门户 | `cd iProduct_Project` → `npm run dev` |
